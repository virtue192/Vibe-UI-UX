# 特效广场与自主投稿（0.5.1）

## 从哪里开始

首页、工作台、接入案例与文档顶部均有「特效广场 / 我的投稿 / 提交特效」。

- `community.html`：5 个内置受控特效与已收录社区案例。官方模板明确标注，不冒充用户作品。
- `community.html?view=review`：正在接收、待审核、合并待发布的真实公开投稿。
- `community.html?view=tracking`：本机主动跟踪的投稿，不是站内登录身份。
- `submit.html`：三步投稿，从工作台携带快照，或者导入效果 JSON。
- `submission.html?id=case-N`：具体投稿、PR 修订、参数、预览与源记录。

## 投稿

1. 在工作台调好支持的单效果，在预览下方点击「提交特效」。已有意图检查仍可能要求确认当前修订的未知项。
2. 投稿页暂存在本次标签页的选定效果快照，不包含密钥、模型设置与完整聊天；工作台后续修改不改变它。
3. 也可直接导入参数效果、原创代码 JSON、合法社区案例或工作台项目。在项目中明确选择一个候选版本。组合与页面片段暂不接受投稿。
4. 填写名称、用途、可选署名与 HTTPS 来源，确认公开分享和 MIT 许可。默认只在当前标签页跟踪；可以主动选择持久保存本机跟踪元数据，不保存源码与凭据到 localStorage。
5. 点击准备投稿，再点击 GitHub 确认链接，登录并按 Submit new issue。若内容太长，页面提供完整可复制正文，粘贴到 Issue 正文再确认。
6. 返回页面刷新，或关联同仓库公开 Issue 链接。只有查询到真实记录后才显示已接收。仅准备或打开链接始终是「尚未确认提交」。

GitHub 仍是最终写入和身份确认入口，普通用户不需要 Fork 或 Token。站内没有伪造 OAuth 登录、自动发 Issue 或授权修改其他作者作品的功能。隐藏署名不会让 GitHub 投稿匿名。

## 状态的真实来源

浏览器只读查询配置仓库的公开 GitHub REST API，不发送 Cookie、Authorization 或 TokenDance Key。当前版本优先保证静态 Pages 可直接工作，采用实时查询；先前设计稿中的 Actions 静态索引同步尚未实施。

- 已接收：找到合法 Issue，等待机器人生成 / 更新精确版本 PR。
- 待审核：官方仓库内、机器人创建、`community/case-N` 分支、main 目标，且 PR 中案例 JSON 与当前 Issue 负载精确一致。
- 已合并、待发布：真实 PR 已合并，但当前官网部署的正式案例数组尚未包含该作品。
- 已收录：以当前部署的 `community-cases.json` 为准；展示的是已部署版本，关闭 Issue 不撤销它。
- 已关闭：Issue / PR 关闭且没有已合并事实；不猜测是作者撤回还是维护者拒绝，源记录保留处理说明。

本版不从未经验证的标签或投稿字段推断「审核中 / 需修改 / 已批准」。具体维护者意见继续在 Issue / PR 中查看。Issue 更新但 PR 尚未同步时退回已接收，不复用旧 PR 的检查结论。

公开 API 有匿名查询额度；按钮节流 60 秒，列表完整分页（上限 20 页，超出会明确失败），查询失败保留当前已经读取的作品，显示问题与 GitHub 追溯入口。不同页面仍可能重复请求；高流量场景应升级为可信静态索引或只读服务端缓存。无凭据查询不保证持续可用，不能对用户承诺实时推送、跨设备身份或即时通知。

## 预览与边界

- 官方和已收录参数效果使用原有 renderer；每页最多 6 个实例，切换、分页与离页释放。
- 未收录内容不会在列表自动运行。参数效果详情显式启动已知 renderer；原创代码详情显式启动既有 sandbox iframe，提供停止入口，不向宿主注入代码。
- 自动契约校验不等于人工行为验证、安全认证或运行性能认证。没有报告时直接显示未验证。
- 当前部署没有收录案例时，展示真实内置特效和真实待审；不会填充设计原型中的示例作品或假审核结果。
- GitHub 外网访问仅在三个社区页面 CSP 中开放到 `api.github.com`；工作台、密钥、TokenDance 请求与原有隔离帧策略保持各自边界。
- 常用导航和状态覆盖五语；新增社区功能的长说明目前中英完整，日 / 韩 / 德缺项明确回退英文，不代表完成所有社区长文翻译。

## 实现文件

`community-app.js` 共用三页；`community-feed-core.js` 推导来源与状态；`community-api.js` 固定仓库只读请求与分页；`submission-adapter.js` 选定快照转合法 v1 / v2；`submission-state.js` 分离会话草稿、本机跟踪和匿名客户端关联 ID。客户端 ID 放在正文封装标记中，不改变现有闭合投稿 schema，不代表作者权限。

`theme.css` 统一米白、浅橄榄绿、字体与卡片，保留效果自身的颜色和交互。`site-shell.js` 提供稳定导航。`plaza.css` 提供社区页的响应式布局。

原有机器人、维护者审核、分支保护、手动合并和正式 Pages 发布不被绕过。无需修改 GitHub Actions 写权限来实现本版的公开列表。
