# IntentKit 0.5 工作台

本轮为本地实现，尚未推送或部署。官网更新需要维护者按仓库流程合并并发布。

## 从一个本地效果开始

运行 `npm run dev`，进入 `/studio.html`。默认是轻微卡片抬升；本地示例、词库浏览、调参、比较与导出不请求模型。

输入描述后用“预览我的想法”匹配配方。已连接时会清楚说明使用 AI 理解；“生成新效果”是单独入口。连接本身不调用生成模型。原有单次请求、无自动付费重试、流式与容量行为保持。

## 候选与版本

“保存为候选”捕获当前实现、有效参数、意图和场景；“保存新版本”在同一候选追加不可变快照。恢复只创建工作副本，不改旧版本。最多 6 个候选，一轮比较 2–3 个快照。

“我的方案”可以命名、恢复、复制和选择；选择绑定确切快照。当前编辑与已选版本不同会提示。比较中的时间轴使用固定 4 秒演示，不能当成真实操作录像。原创代码没有统一确定帧接口，因此只支持独立隔离比较，不启用同步时间轴。

项目工具中可以保存到此浏览器、恢复本机项目、导入或导出项目 JSON。原始输入和逐字证据默认不写入本机或项目备份；代码与规范化约束会保存。密钥和推理正文始终不进入这些文件。浏览器存储不可用时仍可下载 JSON。不存在账号或云端同步。

## 意图和检查

统一 Plan 包装原有配方、组件或原创 artifact；不重写原始源码。Plan.params 是当前参数唯一来源，预览、描述和代码交付共用有效参数。

检查分为 pass / fail / unknown / not-applicable。共享参数校验成功不代表主观效果满足要求；原创初始化成功不证明参数有效、资源清理或语义正确。导入报告先视为历史记录。

用户可以接受当前修订中列出的具体偏离或未知项。相关参数、源码或约束变化后确认失效。原始项目备份可保存未确认工作；正常交付入口保留检查门槛。

原有配方理解 UI 仍可编辑 IR。明确且无歧义的抬升、时长等白名单数值可应用到实际参数；越界、不支持或冲突请求不会被默默夹到合法区间。

## 组合与片段

输入区高级工具内提供三种组合：抬升+按压、按压+波纹、抬升+波纹。一个控制器管理属性和清理；不支持任意叠加。系统触屏和减少动态效果行为保留，原始 transform 不被替换。

四种片段为按钮、卡片组、表单和列表，可编辑内容、参数与声明的状态。表单默认是本地演示；导出后通过 onSubmit 接真实业务。失败保留输入，按压或波纹不代表保存成功。

| 类型 | Web | React | 视频 | 确定帧 |
| --- | --- | --- | --- | --- |
| 5 类既有受控效果 | 支持 | 支持 | 保留原有支持 | 支持 |
| 其余词条预览 | 不提供占位导出 | 不支持 | 不支持 | 未声明则不启用 |
| 原创代码 | 隔离示例+源码 | 不承诺直接适配 | 不支持 | 不支持 |
| 三类白名单组合 | 支持 | 支持 | 不支持 | 支持 |
| 四类片段 | 支持 | 支持 | 不支持 | 当前不对比较器承诺统一同步 |

## 接入案例和 Skill

`/integrations.html` 提供 8 个维护者编写的本地案例。每个案例展示需求、两个参数版本、选择理由、真实业务元素绑定、限制和导出；不表示新增 8 种效果，也不冒充真实付费生成。

工作台可下载 `intentkit-integration.zip`。该 Skill 与内容维护 Skill 分工不同：它读取用户选中的方案，适配已有 Web / React 元素，检查属性冲突、焦点、触屏和清理。独立校验器不联网、不执行原创代码；生成源码仍使用原来的 sandbox。

## 数据和开发

新格式：intentkit.plan/1、intentkit.project/1、intentkit.validation-report/1、intentkit.composition/1、intentkit.fragment/1。新容器通过适配器兼容旧格式，旧导出保留。社区投稿仍使用原有 v1/v2 白名单，新组合与片段不会自动获得投稿权限。

运行现有检查：

```sh
npm test
npm run check:content
npm run check:docs
python scripts/package-source.py
npm run build:pages
```

浏览器检查是本地工具，不随生产页面发布：

```sh
node scripts/prepare-browser-checks.mjs
npm run preview:pages
```

打开 `/Vibe-UI-UX/browser-checks.html`。它使用单独的 IndexedDB 验证数据库，不覆盖正常项目存储。重新执行 build:pages 会移除本地检查页面。

实际 React 宿主：

```sh
npm ci --prefix examples/react-host
npm start --prefix examples/react-host
```

打开 `http://localhost:4182`。宿主会构建真实导出的旧效果 hook、新组合和表单组件，使用 React 18 StrictMode 验证。它是开发测试依赖，不是应用运行依赖；不据此承诺所有 SSR 框架或跨浏览器均已验收。
